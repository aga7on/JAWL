# RE/Debug Broker для JAWL

## Что получилось

JAWL получил единый типизированный слой для семи локальных инструментов:
x64dbg/x32dbg, Ghidra Headless, Frida, WinDbg/CDB/TTD, radare2, Qiling и
Triton. Инструменты не обязаны быть заранее запущены. JAWL выбирает провайдер,
создаёт сессию, а брокер поднимает нужный GUI-процесс или изолированный worker,
проверяет входные данные и сохраняет состояние сессии на диск.

Модели не передаётся огромный перечень низкоуровневых функций. В промпте
остаются семь стабильных действий, а конкретные 35 операций открываются через
поиск только по необходимости. Это уменьшает контекст, снижает число
выдуманных аргументов и позволяет обновлять адаптеры без поломки активного
протокола.

## Архитектура

```text
JAWL / внешний MCP-клиент
        |
        | 7 компактных skills
        v
DebugBrokerClient
  |-- каталог операций + JSON Schema + SHA-256 revision
  |-- журнал событий и долговечные сессии
  |-- ограничение и безопасная сериализация результатов
  |-- автоматический lifecycle провайдеров
        |
        +-- x64dbg/x32dbg: отдельный loopback HTTP-порт на сессию
        +-- Ghidra/radare2/WinDbg/TTD: ограниченные CLI-запуски
        +-- Frida/Qiling/Triton: изолированные JSON-line workers
```

Состояние хранится в `G:\RE\Workspaces\broker`, результаты анализа — в
`G:\RE\Artifacts\broker`. После перезапуска незавершённые сессии помечаются как
`interrupted`, а не выдаются модели за живые.

## Практические исправления

- большие JSON-ответы radare2 сначала разбираются полностью и только потом
  ограничиваются;
- модель всегда получает валидный JSON даже при усечении результата;
- быстрый WinDbg crash-анализ не зависает на загрузке расширений и символов;
- Frida завершает только процесс, созданный самим брокером;
- Qiling возвращает частичный trace при контролируемой ошибке эмуляции;
- x64dbg и x32dbg используют изолированные loopback-порты, экранируют JSON и не
  подхватывают чужой открытый target;
- контекстный callback совместим с аргументами реестра JAWL;
- вызовы через operator control разрешены только для семи broker skills.

## Проверенный живой сценарий

На `jawl_live_target.exe` последовательно проверены:

- radare2: PE-метаданные, функции, строки, дизассемблирование и xrefs;
- Ghidra: полноценный headless-анализ и экспорт 461 функции;
- WinDbg/DbgEng: версия движка и компоненты DbgEng/DbgModel/TTDReplay, реальный
  access violation, регистры и стек с `Program.Crash`;
- Frida: suspended spawn, модули, RPC, resume и корректное закрытие;
- Qiling: ограниченная эмуляция восьми инструкций;
- Triton: исполнение до `RAX=0x2a` и решение symbolic input;
- x64dbg и x32dbg: автоматический GUI-старт, правильная архитектура/target,
  регистры, модули, дизассемблирование и breakpoints.

Тот же маршрут проверен через реально запущенный JAWL:
`search_operations → start_session → call_operation → stop_session`.
Отдельно проверен внешний stdio MCP-сервер и выдача всех семи skills.

## TTD

Официальный standalone TTD 1.11.611.0 установлен в
`G:\RE\Tools\ttd\current`. EULA вручную принята владельцем машины; запись
остаётся доступной только из явно повышенного процесса JAWL. Брокер умеет
показать точный статус и по-прежнему откажется:

- принимать EULA от имени пользователя;
- автоматически вызывать UAC;
- писать trace за пределы `G:\RE\Artifacts\broker\ttd`;
- перезаписывать существующий trace.

Полный живой тест создал 8-MiB trace безопасной x86-цели и затем воспроизвёл его
через DbgEng/TTDReplay с построением 19-MiB индекса. x64 .NET apphost сохранил
системную защиту CET shadow stacks: TTD корректно отказался внедряться, поэтому
тест не отключает эту защиту. Следует помнить, что TTD-трасса способна содержать
секретные данные из памяти процесса.

## Управление

В основном меню JAWL добавлен пункт `D — Debug Broker`. Экран показывает
доступность провайдеров и активные сессии, позволяет запускать/останавливать
сессии, искать операции и выполнить живой self-test. Runtime screen также
показывает состояние брокера.
